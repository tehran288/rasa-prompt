## ۱. سیستم چه کارهایی را خودش انجام می‌دهد؟ (ساعت‌ها به وقت تهران)

| ساعت | کار خودکار | به شما چه می‌رسد |
|---|---|---|
| هر ۵ دقیقه | پایش سلامت: پایگاه‌داده، ربات تلگرام، ربات بله، بودجه‌ی AI | فقط وقتی وضعیت **عوض شود** پیام می‌آید (قطع شد / وصل شد) |
| هر ۳۰ دقیقه | یادآوری سبد خرید نیمه‌کاره (فقط یک بار برای هر سفارش) و منقضی کردن سفارش‌های بالای ۲۴ ساعت | هیچ |
| ۰۳:۳۰، ۰۹:۳۰، ۱۵:۳۰، ۲۱:۳۰ | جمع‌آوری سیگنال‌های ترند | هیچ |
| ۰۲:۳۰ | تحلیل و امتیازدهی ترندها | هیچ |
| ۰۳:۰۰ | تولید پرامپت‌های جدید (به تعداد `INTEL_DAILY_DRAFTS`) | پیام «خط تولید پرامپت امشب» + فهرست صف بازبینی |
| ۰۴:۱۵ | پاک‌سازی داده‌های قدیمی (بیش از ۹۰ روز) | هیچ |

| ۱۰:۰۰ | پست «پرامپت روز» در کانال تلگرام (فارسی + عربی) و کانال بله (فارسی) | پست در کانال‌ها |
| هر وقت شما بخواهید | ارسال همگانی (broadcast) و اطلاع‌رسانی نسخه‌ی جدید به خریداران | گزارش پیشرفت و خلاصه‌ی پایانی |

همه‌ی پیام‌های مدیریتی به گروه/چت ادمین (`TELEGRAM_ADMIN_CHAT_ID` و `BALE_ADMIN_CHAT_ID`) می‌رود.

## ۲. روتین روزانه‌ی ۴۵ دقیقه‌ای

| زمان | کار | کجا |
|---|---|---|
| ۵ دقیقه (حدود ۸:۰۵) | خواندن «گزارش روزانه»: فروش، درآمد، کاربر جدید، هزینه‌ی AI، صف‌ها. اگر هشدار 🚨 قرمزی از شب مانده، بخش ۶ را ببینید. | چت ادمین |
| ۱۵ دقیقه | صف پشتیبانی: تیکت‌های باز را جواب دهید یا پاسخ پیش‌نویس AI را تأیید کنید. | ربات → منوی ادمین → تیکت‌ها |
| ۱۵ دقیقه | صف تأیید محتوا: پیش‌نویس‌های پرامپت (بخش ۵). | ربات → `/review` |
| ۱۰ دقیقه | یک تعامل واقعی: جواب کامنت کانال، گروه‌ها، Reddit. نگاهی به پست ۱۰ صبح. | کانال‌ها |

قانون: اگر یک صف سه روز پشت‌سرهم بیش از ۱۵ دقیقه وقت گرفت، یعنی باید خودکارتر شود — برای هفته‌ی بعد تیکت بزنید.

## ۳. هشدارها را چطور بخوانیم؟

| پیام | معنی | اقدام |
|---|---|---|
| 🚨 هشدار سلامت — پایگاه‌داده: 🔴 قطع | ربات‌ها و Jobها کار نمی‌کنند | بخش ۶-الف |
| 🚨 ربات تلگرام: 🔴 قطع | `getMe` تلگرام جواب نمی‌دهد (توکن باطل، قطعی تلگرام، مشکل شبکه‌ی سرور) | بخش ۶-ب |
| 🚨 ربات بله: 🔴 قطع | مثل بالا برای بله | بخش ۶-ج |
| 🚨 بودجه‌ی AI: 🟠 بیش از ۸۰٪ | نزدیک سقف روزانه (`AI_DAILY_BUDGET_USD`) | معمولاً کاری لازم نیست؛ اگر هر روز تکرار شد سقف یا مسیر مدل‌ها را بازبینی کنید |
| 🚨 بودجه‌ی AI: 🔴 تمام‌شده | تولید پرامپت امشب متوقف می‌شود؛ ربات ممکن است در کارهای AI پاسخ ساده‌تر بدهد | بخش ۶-د |
| ✅ بازیابی سرویس | مشکل قبلی خودبه‌خود حل شد | هیچ |
| ⏸ تولید پرامپت امروز متوقف شد | بودجه پر بوده | فردا خودکار ادامه می‌دهد |
| گزارش روزانه با جمله‌ی «متن خودکار — نویسنده‌ی هوش مصنوعی در دسترس نبود» | AI در دسترس نبوده؛ اعداد درست‌اند | فقط اگر چند روز تکرار شد بخش ۶-د |
| گزارش بدون پیام ساعت ۸ | Worker یا هر دو ربات پیام‌رسان قطع‌اند | بخش ۴ (وضعیت سرویس‌ها) |

هشدارها **فقط هنگام تغییر وضعیت** می‌آیند؛ اگر چیزی قطع بماند، پیام تکرار نمی‌شود تا وقتی وصل شود.

## ۴. دستورهای پایه روی سرور

همه‌ی دستورها از پوشه‌ی مخزن روی سرور (`cd ~/rasa-prompt`):

```bash
alias rc='docker compose -f infra/docker-compose.yml --profile proxy --profile backup'
rc ps                      # وضعیت همه‌ی سرویس‌ها (باید healthy باشند)
rc logs -f --tail=200 worker        # لاگ Worker
rc logs -f --tail=200 bot-telegram  # لاگ ربات تلگرام
rc restart bot-bale        # راه‌اندازی مجدد یک سرویس
```

## ۵. تأیید پیش‌نویس‌های پرامپت (Intel) از داخل ربات

1. ساعت ۳ صبح پیام «خط تولید پرامپت امشب» می‌آید: چند پرامپت خودکار منتشر شده (همه‌ی دروازه‌های کیفیت را رد کرده‌اند) و چندتا «منتظر تأیید شما» هستند.
2. در ربات `/review` را بزنید. برای هر پیش‌نویس عنوان، خلاصه، امتیاز داور، امتیاز اصالت و منابع تحقیق نمایش داده می‌شود.
3. **تأیید** → در کاتالوگ منتشر می‌شود و ممکن است فردا ساعت ۱۰ «پرامپت روز» شود. **رد** → بایگانی می‌شود.
4. معیار سریع: عنوان روشن؟ مثال خروجی منطقی؟ اصالت ≥ ۸۵؟ چیزی شبیه محصول پولی رقبا نیست؟ موضوع با قوانین (سند ۰۹) سازگار است؟ اگر شک دارید، رد کنید.
5. برای کم‌کردن بار: اگر یک هفته بیش از ۹۰٪ موارد را تأیید کردید، می‌توانید `INTEL_AUTO_PUBLISH=true` کنید (یا `INTEL_DAILY_DRAFTS` را کم کنید).

## ۶. وقتی چیزی خراب شد

### الف) پایگاه‌داده قطع است
1. `rc ps` → اگر `postgres` در حالت `unhealthy` یا `exited` است: `rc logs --tail=100 postgres`.
2. دیسک پر؟ `df -h`. اگر پر است: لاگ‌های قدیمی Docker را پاک کنید (`docker system prune` — **بدون** `--volumes`).
3. `rc up -d postgres` و بعد `rc restart worker bot-telegram bot-bale`.
4. اگر داده خراب شده → بازیابی پشتیبان (بخش ۸).

### ب) تلگرام قطع است
- اول ببینید مشکل از کجاست: `rc logs --tail=50 bot-telegram`.
  - `401 Unauthorized` → توکن باطل شده (بخش ۷).
  - `ETIMEDOUT` / `ECONNRESET` → شبکه‌ی سرور یا خود تلگرام. اگر سرور داخل ایران است، تلگرام از آنجا کار نمی‌کند — سرور ربات تلگرام باید خارج از ایران باشد.
- قطعی سراسری تلگرام: کاری لازم نیست؛ وقتی برگردد، پیام «✅ بازیابی» می‌آید. پیام‌های عقب‌مانده را تلگرام خودش تحویل می‌دهد.
- در این مدت گزارش‌ها و هشدارها از طریق بله هم ارسال می‌شوند (اگر `BALE_ADMIN_CHAT_ID` تنظیم شده باشد — حتماً تنظیمش کنید).

### ج) بله قطع است
- `rc logs --tail=50 bot-bale`. اگر از سرور خارج به `tapi.bale.ai` دسترسی نیست، `deploy.md` گزینه‌ی C (polling) یا B (سرور داخلی) را ببینید.
- خرید با کیف پول بله در این مدت ممکن نیست؛ کاربران می‌توانند از لینک پرداخت سایت (زرین‌پال) استفاده کنند.

### د) هوش مصنوعی (AI) کار نمی‌کند
- نشانه‌ها: گزارش با متن خودکار، پست کانال با قالب ساده، پاسخ‌های ساده‌تر ربات. **فروش و تحویل پرامپت‌ها متوقف نمی‌شود.**
- علت‌ها: (۱) بودجه‌ی روزانه تمام شده → تا نیمه‌شب UTC (ساعت ۳:۳۰ تهران) صبر کنید یا موقتاً `AI_DAILY_BUDGET_USD` را بالا ببرید. (۲) کلید API باطل/اعتبار حساب تمام → داشبورد ارائه‌دهنده را چک کنید و کلید را عوض کنید (بخش ۷). (۳) قطعی ارائه‌دهنده → صفحه‌ی status ارائه‌دهنده؛ در صورت نیاز در `AI_ROUTES` کارها را به ارائه‌دهنده‌ی جایگزین (`OPENAI_COMPAT_*`) ببرید.
- بعد از تغییر `.env`: `rc up -d` (سرویس‌هایی که env آن‌ها عوض شده دوباره ساخته می‌شوند).

### هـ) پرداخت کار نمی‌کند
1. لاگ ربات را برای `pre_checkout` / `successful_payment` ببینید.
2. **ستاره‌ی تلگرام:** معمولاً مشکل از تلگرام است؛ صبر کنید. سفارش‌های پرداخت‌شده را سیستم با شناسه‌ی پرداخت به‌صورت idempotent تحویل می‌دهد — پرداخت تکراری دوبار تحویل داده نمی‌شود.
3. **کیف پول بله:** توکن `BALE_WALLET_PROVIDER_TOKEN` را در بله بررسی کنید.
4. در هر حالت لینک پرداخت سایت (زرین‌پال) جایگزین است. یک پیام همگانی کوتاه بدهید: «پرداخت درون‌ربات موقتاً از طریق لینک انجام می‌شود».
5. سفارش‌های معلق بعد از ۲۴ ساعت خودکار منقضی می‌شوند؛ اگر کاربری پول داده ولی چیزی نگرفته، از طریق تیکت پیگیری و دستی تحویل/بازپرداخت کنید.

### و) Worker بالا نمی‌آید
- `rc logs --tail=200 worker`. خطای migration → آخرین نسخه را برگردانید (`IMAGE_TAG` قبلی در `infra/.env` و `rc up -d`) و به تیم فنی خبر دهید.

## ۷. چرخش (عوض کردن) توکن‌ها و کلیدها

> هیچ توکنی را در چت، گیت یا اسکرین‌شات نگذارید. فقط در `.env` سرور یا بخش Secrets در Coolify.

| چه چیزی | کجا عوض می‌شود | بعد از آن |
|---|---|---|
| توکن ربات تلگرام | @BotFather → `/revoke` → توکن جدید → `TELEGRAM_BOT_TOKEN` | `rc up -d bot-telegram worker` (ربات webhook را دوباره ثبت می‌کند) |
| توکن ربات بله | BotFather بله → توکن جدید → `BALE_BOT_TOKEN` | `rc up -d bot-bale worker` |
| `WEBHOOK_SECRET` | یک رشته‌ی تصادفی جدید (`openssl rand -hex 32`) | `rc up -d bot-telegram bot-bale` |
| کلید Anthropic / OpenAI-compat | داشبورد ارائه‌دهنده → کلید جدید → `.env` → کلید قدیمی را حذف کنید | `rc up -d` |
| رمز پایگاه‌داده | `rc exec postgres psql -U rasa -c "ALTER USER rasa PASSWORD '...'"` و بعد `POSTGRES_PASSWORD` در `infra/.env` | `rc up -d` |
| کلیدهای S3 پشتیبان | پنل ذخیره‌ساز → `S3_*` در `infra/.env` | `rc up -d backup` و یک پشتیبان دستی تست کنید |

برنامه‌ی پیشنهادی: هر ۹۰ روز کلیدهای AI و S3؛ توکن ربات‌ها فقط در صورت شک به نشت.

## ۸. پشتیبان و بازیابی

- هر شب یک پشتیبان رمزگذاری‌شده از پایگاه‌داده به ذخیره‌ساز S3 می‌رود و ۳۰ روز نگه داشته می‌شود.
- رمز پشتیبان (`BACKUP_PASSPHRASE`) را در مدیر رمز نگه دارید؛ بدون آن پشتیبان‌ها قابل بازیابی نیستند.

**پشتیبان دستی (مثلاً قبل از به‌روزرسانی بزرگ):**
```bash
rc exec backup sh backup.sh
```

**بازیابی:**
```bash
rc stop worker bot-telegram bot-bale       # اول سرویس‌ها را متوقف کنید
rc exec backup sh restore.sh               # آخرین پشتیبان
# یا یک پشتیبان مشخص:  rc exec backup sh restore.sh 2026-10-07T00:00:00
rc start worker bot-telegram bot-bale
```
بعد از بازیابی: `/start` را در هر دو ربات تست کنید و گزارش فردا را چک کنید.

**تست ماهانه‌ی بازیابی** (روتین ماهانه): روی یک پایگاه‌داده‌ی آزمایشی بازیابی کنید و تعداد کاربران/سفارش‌ها را با گزارش مقایسه کنید.

## ۹. استقرار نسخه‌ی جدید

1. تغییرات در شاخه → Pull Request → CI باید سبز شود (lint، typecheck، تست، build).
2. ادغام در `main`.
3. ساخت نسخه: `git tag v0.4.0 && git push --tags` → GitHub Actions ایمیج‌ها را در GHCR می‌سازد (حدود ۱۰ دقیقه).
4. روی سرور: در `infra/.env` مقدار `IMAGE_TAG=0.4.0` و بعد:
   ```bash
   rc pull && rc up -d && rc ps
   ```
   (در Coolify: دکمه‌ی Redeploy.)
5. ۵ دقیقه بعد: `/start` در هر دو ربات، و نبود هشدار در چت ادمین.
6. **بازگشت (rollback):** `IMAGE_TAG` قبلی و `rc up -d`. اگر نسخه‌ی جدید migration پایگاه‌داده داشت و مشکل‌ساز شد، از پشتیبان قبل از استقرار بازیابی کنید.

## ۱۰. ارسال همگانی (Broadcast)

- از منوی ادمین ربات: انتخاب گروه (همه / خریداران / غیرخریداران / مشترکان)، زبان و پلتفرم (اختیاری)، متن.
- سرعت ارسال خودکار کنترل می‌شود (تلگرام ۲۵ پیام در ثانیه، بله ۱۰)؛ ارسال به ۱۰ هزار نفر در تلگرام حدود ۷ دقیقه طول می‌کشد.
- هر ۲۰۰۰ نفر گزارش پیشرفت و در پایان خلاصه می‌آید (ارسال‌شده / مسدودکرده / خطا).
- اگر وسط کار سرور ری‌استارت شد، ارسال از همان‌جا ادامه می‌یابد و به کسی دوبار نمی‌رسد (حداکثر چند پیام تکراری در یک دسته).
- **بیش از هفته‌ای ۲ بار ارسال همگانی نکنید** — نرخ بلاک ربات بالا می‌رود.

## ۱۱. چک‌لیست هفتگی و ماهانه‌ی فنی (۱۰ دقیقه)

- هفتگی: `rc ps` همه healthy؟ فضای دیسک (`df -h`) زیر ۷۰٪؟ آخرین پشتیبان در S3 تاریخ دیروز دارد؟
- ماهانه: تست بازیابی؛ به‌روزرسانی سیستم‌عامل سرور (`apt upgrade` و ری‌استارت در ساعت کم‌ترافیک، مثلاً ۵ صبح)؛ بازبینی هزینه‌ی AI نسبت به درآمد (هدف زیر ۱۰٪).
